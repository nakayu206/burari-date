# ストア公開チェックリスト

Google Play(Android)に公開するときに、必要なことと、その状況。**公開の準備で、わかったこと**を、ここに残す。
仕組みを変えたとき(取得する情報・外部サービス・課金など)は、[プライバシーポリシー・データセーフティの更新](#仕組みを変えたときに更新するもの)も、忘れずに行う。

関連: [環境構築手順](環境構築手順.md)(署名・RevenueCat・サイト)、[全体設計書](全体設計書.md)

## 1. Google Play Console の入力

| 項目 | 入力する内容 | 状況 |
|---|---|---|
| アプリの作成 | 名前「ぶらりデートガチャ」、パッケージ名`com.buraridate.burari_date`(**あとから変えられない**。AABと一致)、言語は日本語、アプリ、**無料**(アプリ内課金で収益化。公開後に、無料から有料へは、変えられない) | 済み |
| アプリのアクセス権 | ログインなしで基本機能が使える。ゲスト向けの手順を英語で書く。**製品版の申請前に、審査用のテストアカウントを用意する**(下記) | 入力済み(テストアカウントは未) |
| 広告 | **なし**(広告のSDKは入れていない) | 済み |
| コンテンツのレーティング | 「その他のすべてのアプリ」。暴力・性・賭け事・ユーザー間のやり取りは、なし。デジタル商品の購入は、あり。ルートボックスは、なし(ガチャは、駅をランダムに選ぶだけ)。結果は、ほぼ全年齢 | 済み |
| ターゲット層 | **18歳以上**のみ(子ども向けを含めると、ファミリー向けポリシーの対象になる)。「未成年のブロック」は、チェックしない | 済み |
| データセーフティ | 下記の方針で入力。**アカウント削除のURL**も入力 | 入力中 |
| プライバシーポリシーのURL | `https://burari-date.web.app/privacy.html` | 入力する |
| ストアの掲載情報 | 名前・短い説明・詳しい説明・スクリーンショット・アイコン・フィーチャーグラフィック | 素材あり。文章は未 |
| 内部テスト | AABをアップロード(Play App Signing)。審査なし。テスターを登録 | 未(アカウントの種類の変更から72時間後〜) |
| 定期購入の商品 | 月額300円の定期購入。**AABを1回アップロードしてから**でないと、作れない(課金の権限が必要) | 未 |
| 支払いプロファイル・銀行口座 | 組織のアカウント。口座の確認は、少額の入金を確認して、金額を入力 | 入金待ち |

### アカウントの種類について

- 個人から組織への変更は、できる(組織から個人へは、できない)。変更から**72時間は、新しいアプリの提出に、制限がある**。
- 組織のアカウントは、個人のアカウントにある、公開前のテストの条件(一定数のテスターで、一定期間)の対象外。

### 審査用のテストアカウント(製品版の申請前に)

- Googleの審査担当者は、アカウントの新規作成や、自分のアカウントでの購入は、しない。購読中の状態を確認できる、**審査専用のGoogleアカウント**を用意する。
- RevenueCatで、そのアカウントに、**プロモーションの権利**(`burari_date_pro`)を付ける。
- ログイン情報は、Play Consoleの「アプリのアクセス権」だけに入れる(リポジトリ・チャットに書かない)。

### データセーフティの方針

| 種類(Playの分類) | 収集 | 必須/任意 | 目的(Playの項目名) | 補足 |
|---|---|---|---|---|
| 個人情報 → 名前 | はい | 任意 | アカウント管理 | Googleの表示名が、Firebase認証に保存される |
| 個人情報 → メールアドレス | はい | 任意 | アカウント管理・アプリの機能 | Googleで登録したときだけ。お問い合わせの返信にも使う |
| 個人情報 → ユーザーID | はい | 必須 | アプリの機能・アカウント管理・不正行為防止、セキュリティ、コンプライアンス | Firebaseの識別子 |
| 財務情報 → 購入履歴 | はい | 任意 | アプリの機能 | 購読の状態(RevenueCat)。カード情報は、Google Playが扱う |
| メッセージ → その他のアプリ内メッセージ | はい | 任意 | アプリの機能 | お問い合わせの内容 |
| アプリのアクティビティ → その他の操作 | はい | 必須 | アプリの機能・不正行為防止、セキュリティ、コンプライアンス | 履歴・お気に入り・利用回数 |
| デバイスまたはその他のID | はい | 必須 | 不正行為防止、セキュリティ、コンプライアンス・アプリの機能 | 端末の識別子(ランダム) |
| 位置情報・写真・連絡先・アプリの情報とパフォーマンスなど | いいえ | - | - | 端末の現在地は、取得しない。分析・広告のSDKは、入れていない |

- すべて「収集」のみ(「共有」は、チェックしない)。一時的な処理は、すべて「いいえ」。
- 選ばない目的: 分析、デベロッパー コミュニケーション(ニュースや通知の送信用)、広告・マーケティング、カスタマイズ。

- 転送中の暗号化: **はい**。アカウント作成の方法: **OAuth**(Googleログイン)。
- RevenueCat・Firebase・Anthropicなどは、サービスの処理を、代行する会社で、「共有」には、数えない。広告・分析の会社には、共有しない。
- 地図の配信元(OpenStreetMap)に、IPアドレスが、送られる。プライバシーポリシーに、書いてある。

### アカウント削除のURLの条件

`https://burari-date.web.app/delete-account.html` は、次を満たす必要がある。
- アプリまたはデベロッパーの名前に、言及している。
- 削除の手順が、目立つ。
- 削除されるデータと、残るデータの種類と、**保持期間**が、書かれている。

## 2. 素材

| 素材 | 条件 | 場所 |
|---|---|---|
| スクリーンショット | 2〜8枚。PNGまたはJPEG(アルファなし)。各辺320〜3840px。**長い辺は、短い辺の2倍まで**(1080×2400は不可。1080×2160にする) | `C:\Users\kinno\Pictures\burari-date-store-screenshots\`(リポジトリの外) |
| アプリアイコン | 512×512、PNG、1MB以下 | 同上 |
| フィーチャーグラフィック | 1024×500、JPEGまたは24bit PNG | 同上(案) |

### スクリーンショットの撮り方(エミュレータ)

1. 画面の大きさを、2:1にする: `adb shell wm size 1080x2160`(終わったら、`wm size reset`)
2. ステータスバーを整える: `adb shell settings put global sysui_demo_allowed 1` のあと、`com.android.systemui.demo` の放送で、時計(0941)・電池(100)・通知なしにする。終わったら、`command exit`。
3. 時刻による、空の背景(朝・昼・夕方・夜)が、変わる。昼(10〜16時)のタイムゾーンにする(`service call alarm 3 s16 Asia/Tokyo`)。
4. 日本語の入力は、`adb`では、できない。ADBKeyBoard(エミュレータだけ)を入れ、`ADB_INPUT_B64`の放送で、入力する。
5. 容量が足りないときは、デバッグ版ではなく、**リリース版**(`flutter build apk --release --flavor dev ...`)を入れる。

## 3. アプリ・サイトの側で、必要だったこと

| 必要なこと | 理由 | 状況 |
|---|---|---|
| **アプリ内のアカウント削除** | アカウントを作れるアプリは、アプリ内で削除を依頼できること、ウェブの案内があること(Playの規則) | 済み(#190・#191) |
| **プライバシーポリシーの更新** | 取得する情報・外部サービスが、増えたら、更新する。データセーフティの回答と、食い違わせない | 済み(#192) |
| **課金の本番キー** | リリース版は、`kRevenueCatAndroidApiKey`(`goog_…`)が空だと、購入できない | Playのアプリ登録のあと |
| **バージョンコード** | 同じ`versionCode`は、再アップロードできない。`pubspec.yaml`の`version`の`+`以降を、上げる | 初回は`1.0.0+1` |
| **特定商取引法の表記** | 有料のサービスは、運営者名・所在地・連絡先などの表示が、必要。サイトの運営者の欄が、「準備中」のまま | **未** |
| **削除の依頼先の連絡先** | 削除の案内に、公開できる連絡先(メールなど)を、載せたほうが安全 | **未** |
| 同意の版(`kTermsVersion`) | 規約・ポリシーを変えたら、上げて、もう一度、同意を求める | 2 |

## 4. 外部サービスの規約

- **ホットペッパーグルメAPI**: 有料のアプリでの利用は、リクルートに確認した。**書面による同意は不要**(2026-10-08の回答)。条件は、クレジットを、**リクルートの情報の箇所だけ**に表示し、**AIが作った文章と、混同されない**こと。→ 候補の一覧・詳細に、「AI紹介」のラベルと、「店舗情報: ホットペッパーグルメ」を、表示している。返信のメールは、保存しておく。
- **Anthropic(Claude API)**: 月の支出上限を、設定済み($10)。残高の補充は、リリース前に確認する。自動チャージは、オフ。
- **Foursquare・OpenStreetMap**: ポリシーに、書いてある。

## 仕組みを変えたときに更新するもの

取得する情報(収集するデータ・端末の識別子など)や、外部サービス、課金の仕組みを変えたら、次を、そろえて更新する。

1. `lib/presentation/pages/settings/legal_texts.dart`(利用規約・プライバシーポリシー・削除の案内)
2. サイトを作り直す: `dart run tool/build_site.dart` → `firebase deploy --only hosting --project burari-date`
3. 同意の版を上げる(`lib/core/config/terms_version.dart`)
4. Play Consoleの**データセーフティ**を、更新する
5. このチェックリストの、方針の表を、直す
