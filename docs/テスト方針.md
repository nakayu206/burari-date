# テスト方針

kumayokeru-app/tekushare-appと同様、単体テストと結合テストを分けて管理する。

## 基本方針

- **単体テスト**: 1件ずつの責務でテスト。ユースケース・Widgetの表示/操作/状態変化を個別に検証
- **結合テスト**: ユーザー操作の流れをまとめてテスト。画面遷移など複数要素をまたぐシナリオ(今後追加)

## ディレクトリ構成

```
test/                    # 単体テスト。lib/ と同じディレクトリ構成で配置
├── domain/usecases/
└── presentation/pages/

integration_test/        # 結合テスト(今後追加)
```

## 実行コマンド

```bash
flutter test                          # 単体テスト全件
flutter test --reporter expanded      # 詳細ログあり
```

## テスト作成の指針

- テストファイルは`test/`以下に対象と同じディレクトリ構成で配置
- `group`でクラス名・画面名をまとめ、`test`/`testWidgets`で1つの振る舞いをテスト
- Widgetテストの画面サイズは`tester.view.physicalSize`でスマートフォンサイズ(1170×2532)に統一
- PRと同じタイミングでテストを必ず作成する([コード規約.md](コード規約.md)参照)

## 対象別テスト内容

| テスト種別 | 内容 | ツール |
|---|---|---|
| ユニットテスト | ビジネスロジック(`RunGacha`の抽選ロジック等) | `flutter_test` |
| ウィジェットテスト | 画面単位のUI動作確認 | `flutter_test` |
| 結合テスト(今後) | 駅選択→ガチャ→候補一覧の一連の画面遷移 | `integration_test` |

## CI(`.github/workflows/ci.yml`)での実行方針

- PR作成・mainへのpush時に、フォーマット/静的解析/テストを自動実行
- 現時点でIsar等のFFIプラグインは使用していないため、通常の`flutter test`(ヘッドレス)で実行可能
- 結合テストを追加する場合は実機/エミュレータが必要なため、CIから除外する運用を検討する
